# Exporting and publishing n8n safely

## Workflow JSON status

The exact workflow JSON **has not been provided or exported into this repository**. Its architecture, SQL and configured expressions are documented, but an importable `.json` must be generated by the user's own n8n instance. Do not pretend the documentation alone is an importable workflow.

## Export from the n8n editor

Use the workflow's top-right menu and select **Download** (workflow JSON) where offered. Save the original privately, **outside this public repo**. See the [n8n export/import documentation](https://docs.n8n.io/build/manage-workflows/export-and-import/).

### Review the JSON before copying into `workflows/`

- Replace **all personal Gmail recipients** in the approval/supplier nodes with placeholder addresses such as `demo-purchasing@example.com` and `demo-supplier@example.com`.
- Remove or anonymize credential names/IDs and any actual credentials; imported workflows will require the user's own credentials to be assigned.
- Inspect text fields, node parameters, pinned data, HTTP headers, notes, URLs, webhook references, workflow ID/metadata and any embedded data for private details.
- Keep the SQL demo-only SKU filter `POOL-%`; don't expose any real ERP records.
- Confirm the JSON still parses and that no secrets are present. Prefer testing a sanitized import in a disposable n8n environment before publication.
- Never upload credential exports, encrypted backups, decrypted exports, Docker volumes, tokens or a database backup to GitHub.

A normal workflow export **does not transfer working OAuth/SQL secrets**, but exported JSON may still include credential names and IDs, hardcoded email addresses, or parameters that hold sensitive information. Treat exports as potentially sensitive until audited. [n8n migration guidance](https://support.n8n.io/article/migrating-from-cloud-to-self-hosted).

## Demo restoration notes (not a full deployment guide)

- JTL-Wawi 2.2.2, SQL Server 2022 and fictional `eazybusiness` products were used for the original demo.
- SQL: `host.docker.internal:14333` from the local Docker n8n container to the Windows SQL Server host.
- Access: use a **dedicated read-only** SQL account, not `sa`, to execute the documented SELECT.
- Email: use separately configured, personally controlled Gmail credentials and test recipients.
- No JTL database writes are needed or authorized.

The repository is a documented *case study* rather than a one-command installation package.
